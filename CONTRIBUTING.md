# Contributing

Thanks for your interest in contributing. This guide will be updated as the project takes shape.

## Before you start

- Check existing issues and pull requests to avoid duplicating work.
- For a significant change, open an issue first to discuss the approach.

## Development workflow

1. Create a branch for your change.
2. Keep changes focused and follow the conventions already used in the project.
3. Run the relevant tests and checks. Document any checks you could not run.
4. Review your changes before committing.
5. Open a pull request describing the motivation, changes, and verification.

## Commit messages

Use concise messages that describe the change, for example:

```text
Add daily habit completion
```

## Pull requests

- Explain what changed and why.
- Link related issues.
- Include screenshots for user-interface changes when useful.
- Make sure documentation is updated when behavior or setup changes.
